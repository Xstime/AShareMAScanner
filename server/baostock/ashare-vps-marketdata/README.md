# BaoStock VPS 服务器 v1.0.2 开发版

此目录是现有 1.0.1 服务器的开发版源码，并非正式发布，也尚未在用户 VPS 上实测。请勿运行旧版 install.sh 覆盖现有配置；该脚本仅作历史参考。安装/替换前请先备份服务程序和环境文件，并检查现有定时器及正在运行的任务。

## 变化

- BaoStock 股票日线改为不复权 `adjustflag=3`，保持单会话串行请求和原有 API 限额、退避、1.0.1 数据库锁补丁。
- 使用同一数据目录下独立的 `market-unadjusted.sqlite3`，旧 `market.sqlite3` 不修改。首次需要重新采集历史；只有完成度和历史就绪覆盖率满足配置后才替换公开快照。
- 快照表结构、字段、ZIP 内文件名、清单格式与 v1.5.0 客户端约定保持一致。清单标记为不复权。
- 如指数日线落后于交易日历，或采集期间最新交易日变化，保留上一快照。检查指数不代表验证每只股票都已经最终更新。
- 历史数据核验代码与日期范围；日线核验股票代码及日期。此版本不能确认用户所报错位的根因，客户端的旧缓存、备用数据源、涨幅计算和显示逻辑均未改变。

## 升级与运行注意

先在独立环境测试，不要直接执行此目录下的旧 install.sh。旧版环境文件中的 `ASHARE_HISTORY_DAYS=80` 会覆盖本版默认值；若要采集最多 120 个交易日，需明确设置 `ASHARE_HISTORY_DAYS=120`，并确认 BaoStock 日历查询范围及客户端历史需求。首次采集约数千次串行请求，持续时间取决于网络和数据源，可能需要较长时间；不可并发或用频繁重试规避限额。

升级必须确认旧任务已停止、程序文件和配置已经备份、定时任务路径正确。构建测试时必须设置独立的 `ASHARE_DATA_DIR`（包括独立 public 目录）；若直接使用线上数据目录，构建完成会立即自动发布新快照。请先在隔离环境核对快照和客户端，再规划切换。服务器数据目录和 public 目录必须按现场部署核对；本分支不会自动部署或修改 Nginx、限速或定时器。不要删除旧数据库及快照作为升级步骤。`latest.json` 与 `snapshot.zip` 在发布切换期间仍可能发生竞争，v1.5.0 校验失败会拒绝导入。

旧客户端仅替换快照日期范围内本地记录，范围以外的旧后复权数据仍可能留存。客户端备用 AKShare 仍是后复权，除权日涨幅也可能不同于交易软件。上线前必须用真实客户端数据库和至少一只真实股票检查数据口径、历史窗口、日期、价格和涨幅；如果需全路径一致，应另行更新客户端。本开发版未完成真实 VPS / BaoStock 联调，不能声称已修复全部问题。

## 验证

在本目录运行 `python -m unittest discover -s tests -v`。测试使用模拟数据，不访问 BaoStock。

兼容性集成测试使用 v1.5.0 原始客户端同步代码，并在本地 HTTP 服务上检查首次导入、同日快照变化重新下载、未变化时复用缓存及保留客户端自有表。先将 v1.5.0 .pyw 源文件放在本地，再执行 `ASHARE_CLIENT_150_FILE=/path/to/v1.5.0.pyw python -m unittest discover -s tests -v`。未设置路径时该集成测试会跳过。测试使用模拟行情，未覆盖线上 VPS、真实客户端旧数据库与全部策略。

手动回填指定交易日可在隔离环境使用 `python -m ashare_server.cli update --as-of 2026-11-11`。指定日期必须为已到来的有效交易日，且当日日线和完整率满足发布要求。该选项仅影响本次执行；默认定时更新不使用它。切勿把指定历史日期的快照直接覆盖比它更新的线上快照。
